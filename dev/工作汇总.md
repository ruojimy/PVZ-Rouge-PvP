做过的优化（每步都重跑 `tools/check_all.sh`，五场景保持完全一致）：
- 运行时：Box 非原子侵入式引用计数；大字典开放寻址扁平索引（替代 unordered_map 节点）；`Args` 4 元素内联小缓冲；
  全局小对象分配器 `src/core/alloc.cpp`（线程本地 16 字节分级空闲链表，替代 Windows 堆）；MatchNS/DynNS `call_method` 直达；
  `callm` 内建方法名改符号整数比较；手写代码里 `V == "字面量"` 每次驻留字符串的热点（HeroProxy）。
- 翻译器：`x.get()/x.append()` 内联快速路径；`a, b = x, y` 不建临时元组；`any/all(生成器)` 短路；
  `for k, v in d.items()` / `for i, x in enumerate(s)`（循环与推导式）不逐项建元组（enumerate 改为与 Python 一致的实时迭代）。
- 手写：`PeriodicTargetsPy.begin/restore`（`src/sim/pvp/hand/periodic.cpp`，Python 版同样有 C++ 孪生实现）。
- 剖析工具：`PVZ_PROFILE=1`（采样）+ `PVZ_PROFILE_FOCUS=函数`（归因到生成代码）/ `PVZ_PROFILE_UNDER=函数`（子调用分解，
  `PVZ_PROFILE_SKIP` 跳过胶水帧）；`PVZ_ALLOCSTAT=1`（分配尺寸直方图）/ `PVZ_ALLOCSTAT=<字节数>`（该尺寸分配的调用栈）。
- 剩余大头：区段里对 PvP 闸门链的动态调用、`[x, y]` 等小列表（Python 语义本身）、字符串拼接的驻留。进一步需要类型特化（见待办）。
