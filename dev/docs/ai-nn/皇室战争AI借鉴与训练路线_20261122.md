# 皇室战争 AI 借鉴与训练路线（2026-11-22）

本文把截至 11-22 的选卡、局内训练结果，和社区公开的皇室战争 AI 做法合在一起，定出下一阶段路线。正式 AI 仍是 r22，本文不改变任何发行内容。

## 1. 现状

### 选卡：已经跑通

- 做法：用 r22 对 r22 的对局结果（PvP75，9061 局）训练牌组估值网络，再用搜索选卡，并蒸馏出快速选卡头。估值网络 logloss 0.327，AUC 0.96/0.95。
- 72 组盲测，对手按卡牌价值选卡：
  - 搜索选卡：植物真胜 7→28/36，僵尸真胜 30→36/36。
  - 修正后的快速选卡头：僵尸 36/36，植物 7/36（与对手持平）。
- 缺口：
  - 植物蒸馏数据只有 508 局搜索。
  - 还没和 r22 现有选卡直接比过。
  - PvP75 在双方都用 r22 时僵尸真胜 77.5%，偏向僵尸。

### 局内：三周没有可晋级的权重

已经试过的做法：

- r22 策略头的行为克隆
- 残差修正（输出零初始化，起点等同 r22）
- 事件触发入口
- 单招换头
- 同局面续打
- 双种群进化（v2，25 轮只有 1 次植物晋级）

共同结构：

- 网络是几万参数的小 MLP / DeepSet，只接管 r22 的少数战略输出（经济目标、攻守模式、墓碑等）。具体出什么兵、放在哪里，仍由 r22 执行。
- 优化靠"变异 4 个候选 → 每层几局配对筛选 → 守擂"。只有整局胜负这一个信号，样本也只有几十局。

判断：瓶颈不在网络大小，而在信号太弱。
- 进化法每个候选只看到少数几局的二值结果，噪声大于改动本身的效果。
- 网络只能调几个旋钮，r22 的执行层把大部分可学空间锁死了。

## 2. 皇室战争开源 AI 的做法

主要参考 [cr-rl-public](https://github.com/Superbaaaaber/cr-rl-public)（MIT），这份公开的流程最完整。另参考 [FirstLight CR](https://github.com/Jaasssoooonnnnn/FirstLight_CR)、[ClashMaster](https://github.com/rajerthat1/ClashMaster)、[RoyaleFish](https://github.com/fabiospalla9-tech/RoyaleFish)。"打到世界第一"只见于 B 站视频标题，没有可核实的来源。FirstLight CR 自称专精卡组打到名人堂，也未经第三方核实。

| 环节 | 皇室战争 AI | 我们现在 |
|---|---|---|
| 网络控制什么 | 直接出牌：不出 / 第几张手牌 / 技能，再按卡选格子 | 只调 r22 的几个战略旋钮 |
| 决策时机 | 每 0.25 秒一次 | r22 自己定时，网络在重规划时介入 |
| 观测 | 网格 CNN + 单位列表 Transformer + LSTM 记忆 | r22 规划器输入的摘要特征 |
| 隐藏信息 | 策略头只看公开信息；训练时价值头额外看对手手牌和圣水 | 未区分 |
| 起点 | 约 25 万场人类高分对局的行为克隆 | 行为克隆 r22 的战略输出 |
| 优化 | PPO + GAE，按步计算优势；全程加对行为克隆模型的 KL 惩罚 | 进化法，只用整局胜负 |
| 对手 | 先打固定陪练（胜率 45%→89%），再联赛：80% 当前策略，20% 按 PFSP 抽历史快照 | 双种群守擂，r22 作锚 |
| 卡组 | 30% 固定一套，70% 从 505 套牌池按 PFSP 抽 | 自由 / 轮选 / 模板三层 |
| 评测 | 固定对手组，用 Bradley-Terry 拟合 Elo | 配对真胜、超时、出兵节奏 |
| 规模 | 一张 4090 约两周，约 7.2 亿步 | — |
| 已知问题 | 3.8 亿–4.3 亿步进入平台期；学习率调大 6 倍反而变差；英雄技能几乎学不会用 | — |

皇室战争是对称规则，只有卡组不同，也没有轮选和禁卡。我们是真正的不对称：植物和僵尸要用两套策略、各自的对手池，Elo 也分开算。选卡那一层只能靠我们自己的估值搜索。

## 3. 融合方案

### 原则

1. 选卡继续走"估值 + 搜索 + 蒸馏"，这条线已经被证明有效。
2. 局内改成皇室战争式：网络直接出牌，用梯度强化学习。进化法停用。
3. 样本预算远小于皇室战争，所以：
   - 起点必须是 r22 的克隆；
   - 用 KL 拴住，不从零学；
   - 决策点沿用事件触发，而不是固定 0.25 秒，以减少无效步数。

### 规模估算

- 当前产出：5 路并行时，r22 对 r22 每小时约 1180 局。笔记本有过两次过热重启，长期按 5–8 路算。
- 皇室战争第二阶段（固定陪练，胜率 45%→89%）用了约 5000 万步，按每局约 720 步折合约 7 万局。我们大约需要 3–4 个通宵。全量联赛的约 100 万局做不到。
- 所以要分两层：
  - 先求"复制 r22，再在 r22 和陪练身上稳定超过它"；
  - 能否做到全面超过，看第二阶段的曲线再决定。

### 阶段 0：基础设施（约 1–2 天）

- **执行端与学习端分离**：
  - 执行端在 C++ 里跑：`headless_match` 已经能加载 `model.json` 做原生推理，在此基础上扩展为按概率采样动作。
  - 每个决策点记录：观测、动作、log 概率、价值，以及只给价值头用的特权观测。
  - 学习端用 Python 读轨迹，做 PPO 更新，导出新权重，执行端按轮重新加载。
  - 这样避免 Python 逐步驱动带来的开销。
- **PyTorch 换成 CUDA 版**：当前装的是 `2.12.1+cpu`。RTX 5080 笔记本版需要支持 Blackwell 的 CUDA 构建。小网络在 CPU 上也能训，所以这一步不是硬门槛。
- **吞吐基准**：测执行端每小时局数、每局决策数，以及推理占用的时间。

### 阶段 1：动作级策略 + r22 行为克隆（约 2–3 天）

- **动作空间**（植物、僵尸各一套）：
  - 第一步选"等待 / 第几卡槽 / 秘籍 / 英雄技能"；
  - 第二步按选中的卡选位置：植物是格子，僵尸是来源墓碑 + 目标格子；
  - 用合法性掩码屏蔽资源不够、冷却中、无法放置的选项。
- **决策时机**：沿用 11-18 的事件触发（墓碑建成或被毁、冷却完成、资源够付），另加一个最长间隔的兜底。
- **观测**：
  - 地图网格通道：单位、植物、墓碑、地形；
  - 单位列表，用小 Transformer 或 DeepSet；
  - 全局量：阳光或脑子、卡槽冷却、计时、双方英雄状态；
  - 对手已公开的出牌历史和已暴露的秘籍；
  - 一个小的循环层作记忆。
  - 特权观测只进价值头：对手资源、冷却、未暴露的秘籍。
- **数据**：重新跑 r22 对 r22，并保留决策记录。9061 局语料只存了结局（sqlite 只有 7.9 MB），不能直接复用。卡组覆盖三层：轮选、模板、搜索选出的卡组。
- **晋级门槛**：克隆策略对 r22 配对接近 50%，出兵节奏不低于 r22。达不到就不进阶段 2，这是 KL 锚点的前提。

### 阶段 2：PPO 对固定陪练

- 奖励：真胜 +1，负 −1，超时 0；保留 v2 那个对称的结束时间项，让赢得快、输得慢有区分。不给中间奖励，避免学会拖局。
- 优势估计用 GAE，价值头带胜率先验。对行为克隆策略的 KL 惩罚系数先大后小。
- 对手：植物练的时候对手是冻结的 r22 僵尸，僵尸同理。双方轮换，每次只练一方。
- 卡组：30% 固定在少数几套高价值卡组上（专精），70% 由估值网络从三层牌池里抽。
- 低频动作：秘籍、英雄技能、前体保护。皇室战争 AI 学不会用英雄技能，原因就是这类动作频率太低。预防措施：
  - 第一步动作头的熵设下限；
  - 行为克隆中按类别加权；
  - 单独统计使用率，低于 r22 的一半就报警。
- 评测：对固定对手组（r22、行为克隆、历史快照）用 Bradley-Terry 拟合 Elo，植物、僵尸分开算。晋级口径照旧：保住旧胜、旧败转真胜、败转超时、出兵节奏。

### 阶段 3：联赛，并和选卡闭环

- 对手池：80% 对方当前策略，20% 按 PFSP 抽对方的历史快照。r22 永远留在池里作锚。
- 局内策略升级后，用新策略重新生成牌组估值语料，重训估值网络和选卡头。这样"会玩什么牌"和"选什么牌"一起进化，接近 AlphaStar 联赛的做法。
- 平台期的处理：学习率只降不升。要加宽网络时，用保持输出不变的扩宽。

## 4. 同时进行的选卡收尾（只用 CPU，可以夜里跑）

1. 和 r22 现有选卡直接对比，双方都用 r22 操作，约 1 小时。
2. 只收集植物方搜索选卡数据约 2000 局，然后重训快速选卡头，约一个通宵。
3. 难度档位：选卡时加随机扰动。

## 5. 风险

- 机器过热。并行固定在 5 路，训练和数据生成不同时满载。
- 卡表变化。动作空间按卡槽编号，不按卡名，新卡只需要补卡牌特征。但每次卡表变动后，行为克隆数据要重新生成。
- 生产路径。网络进入游戏仍走原生推理。要改生产内核，按 AGENTS.md 修改 typed72 的生产源，而不是早期的 `src/sim/typed/`。
