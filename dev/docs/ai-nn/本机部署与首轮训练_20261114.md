## 首轮训练

每图昼/夜各三个种子，共 72 局无禁卡轨迹，每局上限 600 游戏秒；27 植物胜、12 僵尸胜、33 超时，0 崩溃、0 AI 异常。超时保留在分母中。每阵营每四条规划记录采样一条，得到 11016 条；去除跨分区完全相同的编码/标签记录后为 11004 条。

| 分区 | 地图数 | 记录数 |
| --- | ---: | ---: |
| 训练 | 7 | 6678 |
| 验证 | 2 | 1636 |
| 测试 | 3 | 2690 |

留出地图为要塞、遗迹、铁道。按整张地图分区；种子数值及部分卡组仍有跨图重复，因此这里只声称地图分离，完整记录/编码没有跨分区重复。

网络读取全局/英雄/策略记忆，以及每个存活单位的当前数值和行为类型；不输入卡名或实体 ID。共享单位层为 8 维 ReLU，分别对敌我单位求和/最大值，再经 32/64 隐层输出。变长单位集合不按数量截断。卡组优先级和配额沿用 r22，因此尚未训练独立卡组网络。

三组参数：隐层 32、lr=.003；隐层 64、lr=.003；隐层 64、lr=.001。各 30 epoch，只按验证损失选权重。选中 64、.003；CPU 训练/评估循环耗时 64.60 秒（不含前置读盘）。训练环境为 Windows Python 3.13.14、PyTorch 2.12.1+cpu、4 线程。

- 生成器 28 项测试及真实 `--check` 通过。
- Windows 使用真实 SDL，Linux 使用附件 shim；当前纯无头二进制 `nm` 检查无 V/PyObj/PyError/Box/gil 符号。

- 模型实际对局的跨系统复核为 005 植物、054 植物、090 僵尸三组，完整终局/日志/RNG 一致；其中 005 是入口冒烟，其他两组来自留出地图，不把入口样本用作强度提升证据。

- 生产 r22 规划审计 16/16；隔离真实 AI 房间 15 秒通过，native projection 为 0，七项探针计数为 0。
- `cpp_tests` 在 framework 229 项中遇到 1 项帧像素对象身份断言失败，后续注册套件未开始；不能称全量产品通过。相关框架/性能源码与当前 r2 Git 基线相同，仍需独立复核。

## 本机使用

在项目根目录 PowerShell 中：

```powershell
# 一局 Windows 原生网络策略对 r22；不打开正式游戏，不写玩家存档
./build/ai-nn/run-research.ps1 -Mode Play -Id 005 -Seat plant

# 三张留出地图的全部变体；每次写入新的输出目录
./build/ai-nn/run-research.ps1 -Mode Evaluate -Seat plant
./build/ai-nn/run-research.ps1 -Mode Evaluate -Seat zombie

# 重训三组参数；输出目录必须不存在
python -X utf8 build/ai-nn/train.py --data test_results/ai-nn-local-20261114/dataset.jsonl --out test_results/ai-nn-local-20261114/new-training

# 从 checkpoint 微调，Adam 状态重新初始化
python -X utf8 build/ai-nn/train.py --data test_results/ai-nn-local-20261114/dataset.jsonl --initial test_results/ai-nn-local-20261114/training-v1/selected.pt --out test_results/ai-nn-local-20261114/new-finetune
```

Windows 构建使用仓库 SDL 和 MSVC，`AI_NN_GZIP=OFF`，加载已验证的 plain 语料；Linux 使用完整 zlib。模型推理为 C++ 前向，训练使用本机已有 PyTorch。编译命令、来源和入口见 `build/ai-nn/README.md`。
