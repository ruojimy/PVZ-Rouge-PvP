# PvP72 R8：安卓交互与存档验收

2026-11-04。最终候选为R8，Android versionCode **1104008**；正式文件以 `dist/PVP72-20261104-release-manifest.json` 为准。本文取代早期调查稿及R3/R4“尚未操作ADB”的状态描述。

## 卡死根因与修复

在API35虚拟机上实际复现了：首页→本地演练→确认地图→点稻草人→右下角确认禁用，随后画面和倒计时停止。命令与房间刷新已经返回，SDL线程却持续高CPU；下一帧在第9张僵尸秘籍——玉米卷——的图标生成处阻塞。

图案首次生成用集合处理249×195、共48,555个像素坐标。Android libc++数值哈希的低位与旧桶索引组合后，所有坐标从同一个桶探测，导致极端退化。`src/core/value.cpp`只在私有集合索引中加入64位混合，同时修正插入、查找、删除和搬移索引；公开哈希与元素顺序保持原语义。

实际Android libc++独立探针确认：旧48,555键集中在1个起始桶；混合后分布至15,552个起始桶，单桶最多17键、最长插入探测距离60。原版与原生玉米卷96×96 RGBA的36,864字节完全相同。最终APK正常启动、未启用诊断脚本或UI调用追踪，真实确认操作后图标正常显示，倒计时由28秒继续降至24秒。

## 补齐的输入、USB与文件接口

- `src/pg/system.cpp`此前丢弃4种APP前后台通知和2种渲染器重置通知，现转交给已有应用处理分支。触屏测试覆盖长按阈值、缩放、尺寸变化与后台取消；渲染重置测试只证明通知转换，未模拟真实GPU失效。
- SDL2.28.5的USB混合广播注册在target35上抛出异常。`android/prepare_sdl_java.py`校验原源码SHA后，仅在组包副本回补接收器标记及USB权限Intent包名；外部依赖缓存、另8个Java文件和4个SDL原生库保持原字节。最终虚拟机冷启动出现正常初始化记录，3种USB广播注册成功，原初始化异常消失。物理USB/蓝牙手柄操作尚未验证。
- `os.fsync`曾是空实现，两类文件的`fileno()`都恒为3。现在临时文件和普通文件共用真实FILE*/OS描述符，执行POSIX fsync或Windows _commit，保留读写位置及UTF-8/BOM、bytes、文件模式行为，并修复中文临时前缀与追加模式初始位置。错误会返回异常；Windows对非法FD的线程局部CRT策略会恢复，避免终止进程。

## 保留的失败与验收边界

曾观察到一份R6 guest旧回放由完整变为空文件，唯一原因尚未定位。正常应用启停未改变另一份有效回放，不能把旧异常直接归因于关闭房间或虚拟机关机。原空文件、完整host副本及原始SHA均保留；在QA虚拟机中显式恢复完整旧副本后，才执行本次有效旧档升级和同步冷启动验证。真实文件同步修复针对已确认的空接口，不声称追溯性证明了该旧异常的唯一根因。

铲除的两轮红色测试也保留：审计工具先把点击前时刻误当作真正提交时刻，触屏实际在抬指提交。最终断言仅等待首次权威时钟超过该次accepted输入的精确提交时刻，立即检查同一实体消失，并保留单次输入、原生死亡标记和首帧快照。没有修改生产铲子规则或放宽移除目标。

参考阵容与逐回合AI的花盆强制预留约束尚不完全一致，可能推荐合法但不带花盆的家院阵容。出生屋顶不能直接种普通植物；地图有27格可用草地，本轮已实际移动到草地种植并铲除。此项是策略质量与开局便利性缺口，不能据此声称整图无法种植。

旧全套2366执行身份的2324 PASS、30 FAIL、12 ERROR属于历史版本，本轮没有重跑全套或新增豁免。此前战斗专项另有1个Python夹具缺失失败；不把这些红色历史结果改成R8通过。

本轮采用API35 x86_64虚拟机，经ARM64原生桥运行正式APK；单次战斗样本PSS约629.6MiB、RSS约728.8MiB，包含转译环境影响，**不是峰值、内存优化百分比或手机数据**。R4历史实机FPS与Windows绘制微基准不自动成为R8手机性能结果。实体手机FPS/温升、真实多人联机、全部2v2席位组合、Android软键盘、多指、物理手柄及真实GPU重置仍未全面验收。SDL依赖仍为4KiB ELF对齐，不宣称16KiB页设备兼容。

交付后`dist`仅保留本轮Windows ZIP、APK、源码检查点及校验和、发布清单7项；独立本机游玩目录和AppData玩家数据由发布脚本前后逐文件核对。开发工具的独立交付保留在调查目录，不混入主交付目录。
