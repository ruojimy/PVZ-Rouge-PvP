# PvP74.3 自动实机场景

用户无需逐张选卡或手动摆单位。手机本地使用正式 APK 自带的诊断启动参数；联机使用独立的 `pvp743_device_network_fixture`，通过生产 Application、Room 和性能 Driver 创建战斗，手机仍运行正式 APK。联机只需加入一次私有房间，随后自动连续切换场景。

## 手机本地场景

入口：`tools/pvp743_android_scenes.py`，计划：`tools/pvp743-device-scenes.json`。先用 `adb devices` 确认用户授权的实机序列号，然后运行：

```powershell
python -X utf8 tools/pvp743_android_scenes.py --adb C:/Users/xiech/android-sdk/platform-tools/adb.exe --serial 10.191.219.238:44677 --plan tools/pvp743-device-scenes.json --out test_results/pvp743/device-new-run --build 1.6.0.74.3-typed.20261114 --installed-name 1.6.0.74.3-typed.20261114-r3 --code 1114083
```

输出目录必须不存在。脚本核对 APK 版本，在独立诊断存档中执行固定地图、卡组、单位数量、5 秒暖场和配置时长；保存报告、画面、实际设备截图、温度、内存和应用日志。每组前检查电池温度，达到 40°C 则停止。它会关闭正在运行的游戏并重启诊断，不卸载、不清除应用数据；结束后游戏关闭。

## 联机自动场景

构建目标：`pvp743_device_network_fixture`。运行入口：`tools/pvp743_device_network_scene.py`。默认四组为普通 20、混合 120、高弹幕 240、抓人草 120；`--seconds` 设置每组测量时长，也可用 `--plan` 传入 JSON 数组，每项含 `scenario/units/seconds`。限制为 1–4 组、每组 1–300 单位、1–90 秒。

```powershell
python -X utf8 tools/pvp743_device_network_scene.py --out test_results/pvp743/cloud-new-run --endpoint 47.119.190.111:24562 --bind-ip 10.191.175.2 --interface 22 --seconds 30 --adb C:/Users/xiech/android-sdk/platform-tools/adb.exe --serial 10.191.219.238:44677
```

上面的 IP、接口索引和 ADB 端口是 2026-11-16 现场值，换网络后必须重新确认。`--bind-ip/--interface` 只绑定测试上游 socket，绕开本机 TUN，不修改系统路由或代理；无此需要时同时省略。连接使用回环转发的一跳，因此结果不能冒充默认路由直连 WAN 基准。

脚本打印私有房间码；手机加入后自动开始。手机若需自身性能记录，加入前点击基础记录，结束后先点击“导出当前记录”、拉取导出文件，再点击“停止并保存”。r3 在停止后没有导出旧记录的入口。脚本自动保存每组手机截图；手机掉线、未加入、主机提前退出必须查看原始报告，不能仅以脚本启动成功判定通过。

主机是复用生产库的无窗口测试程序，并非发布 PC EXE 的显示验收；真实 LAN 发布 EXE ↔ APK 记录应单独报告。高生命值维持压力，原生 AI/碰撞/伤害继续运行；抓人草预先推进两个生长阶段。联机保留实时输入及心跳，不是确定性输入 A/B。测试启动器不替换正式启动器，也不使用本机独立用户存档。

## 当前证据

本次原始数据在 `test_results/pvp743/device-r3-20261116/`：`diagnostics/` 是四组正式 APK 本地场景；`cloud-fixture-r2/` 是首次完成的四组联机；`cloud-fixture-r3/` 是带自动手机截图的复测。首轮失败 `cloud-fixture/failure.json` 保留。正式 r3 的高负载性能仍未达标，自动布景成功不等于性能验收通过。
