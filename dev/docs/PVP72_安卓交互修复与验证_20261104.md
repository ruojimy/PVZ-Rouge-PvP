# PvP72 安卓交互修复与验证

状态：本文件为初始调查稿，保留当时的待验证项。最终结果已由 [R8安卓交互与存档验收](PVP72_R8_安卓交互与存档验收_20261104.md) 取代，不能把下方旧“待完成”当成当前状态。

## 已复现的卡死

Android API35 虚拟机实际操作：首页→本地演练→确认地图→点稻草人→右下角确认禁用。确认命令正常返回，但下一帧绘制僵尸秘籍时卡住，SDL线程持续占用CPU，画面与倒计时停止。原始截图、线程与调用日志保存在 `test_results/android-interaction-audit-20261104/emulator/trace-probe2/`。

阻塞点是玉米卷图标首次生成。图案算法用集合处理249×195共48,555个像素坐标；Android libc++的数值哈希保留浮点数位模式，原私有集合索引直接截取低位，导致这些整数坐标全部从同一个桶探测，出现极端退化。Windows MSVC采用不同哈希，原桌面检查没有触发。

`src/core/value.cpp`在私有集合桶索引前加入64位混合，并同步处理查找、插入、删除、搬移后的索引。公开哈希、元素顺序和图案算法保持原语义。集合增删查覆盖全部48,555坐标；原版与原生玉米卷图案96×96 RGBA的36,864字节完全一致。

## 输入与显示事件缺口

多分辨率触屏审计又复现：底层SDL转换丢弃APP前后台事件，按下确认→进入后台→抬指会错误提交。显示设备重置事件的透传也在本轮核查范围内。修复及最终分母以候选验证记录为准，不能把初始失败改写成通过。

## 待完成及证据边界

需验证最终签名APK覆盖安装后的原始点击、倒计时、完整选卡到战斗、实际出兵、暂停恢复、返回及前后台切换；再替换交付包和独立本机游玩文件，核对存档不变。

本轮桌面与虚拟机数据不能当作ARM手机FPS。此前实机自动战斗性能报告属于R4，不是选卡界面验收，也不自动成为本轮修复包的性能数据。旧全套测试2366执行身份中仍有30 FAIL、12 ERROR，本轮没有重跑全套或新增豁免；战斗专项旧用例另有一项Python夹具缺失失败，原始结果保留。
