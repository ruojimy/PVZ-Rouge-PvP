# PvP74.2 性能优化与交付验收

状态：最终全量r4和三模式门禁已完成，未新增失败；PC r2及签名APK r5已核验。Android同场景实机性能仍待当前无线调试端口，群友两类崩溃仍未复现。

## A. 原有架构与热点

生产内核在 `build/typed72-integrated-v44/source/src/sim/typed/`，组合来源在 `build/typed72-match-v1/`。PC和Android编译相同生产C++、UI、空间查询与绘制代码，平台层只处理SDL、生命周期、文件选择、打包和原生性能提示。

本轮证实的热点包括：ContentQueries调用方按植物重复枚举敌人；抓人草头部占格反复扫描全植物；NativeFrame显示发布经JSON中转；动画配方反复JSON编码；空白NativeArt画布立即分配大块像素；前台客机移动心跳让房主逐条刷新后再按帧刷新；TLS小对象池跨线程释放后不能回生产线程复用。原生射线及NativeTracking活体几何校验仍有剩余遍历。

## B. 算法与正确性约束

MovingCoverageGrid按地图tile大小分桶，保守登记身体、头部、滚桶及跨格范围；区域查询去重并保留原roster顺序，再调用原精确范围/角度/碰撞判定。覆盖格集合未变时复用候选，格内移动仍重新精判。缓存最多256区域、4MiB；巨大或非法范围走保守回退。阵营、魅惑、血量优先级、穿透和伤害继续使用原规则。

原生行列/邻近索引和共享Flood寻路场继续复用。最近目标按原距离规则选择，不改成路径距离；雪人按目标格共享有界路径bank。鹦鹉/乌鸦保留路径拦截，甜薯保留优先级。猫尾、抓人草属于实体追踪，无需为飞行弹幕复制反阵营地面流场。地下、飞行、车辆、跳跃、梯子、集结、跟随等仍走原特殊控制。范围查询与寻路网格可以共享基础设施，不要求同精度。

32组反向订阅原型已比较：低运动、频繁窄范围感应有益，频繁移动/大范围时更慢且更费内存，生产采用主动局部查询和候选缓存。没有用不完整事件钩子降低感应精度。常见开销目标接近索引维护+实际查询+局部候选+必要路径更新，依赖空间分布；密集或全图范围仍可能接近P×Z或B×Z，不是最坏复杂度保证。
