# PvP74.3 r3：快照排队与高负载联机

交付修订为 `pvp743-r3`。联机与回放兼容标识继续使用 `1.6.0.74.3-typed.20261114`；安卓包使用独立修订后缀和递增 versionCode。构建、封包、全量回归与实机验收分别记录，以本次发行清单为准。

## 本次改动

- 后台快照打包直接读取已冻结数据，JSON、压缩和 Base64 阶段释放原生运行时锁，减少对主线程的阻塞；不支持的输入仍走原兼容路径。相同输入的压缩载荷逐字节一致。
- 工作线程容量用尽时等待下一份新快照，不在主线程临时执行昂贵的同步打包。
- 每个玩家连接保留尚未发送的最新同流快照。地形全量前置包、普通消息顺序、重连代际和网络序号保持；慢连接暂不展开下一帧，其他玩家继续收发。
- 限制原生 TCP 与中继桥接两端的系统缓冲，配合已有桥接缓冲上限，让拥塞更早反馈到可合并的快照队列。
- 接收端使用真正有输出上限、校验压缩流完整性的解压路径，拒绝截断、坏校验及多余尾部；限制解压膨胀时的临时内存。
- 带入已验证的预览/关局引用环修复、内容僵尸眩晕绘制高度表修复。神经网络 AI 本轮没有训练或调整策略。

## 已取得的网络证据

同一台 PC、两逻辑核、300 单位真实房间的固定快照、3 个接收者、24 次实际工作线程任务，A/B/B/A 对照：

| 指标 | 原路径 | 新路径 |
| --- | --- | --- |
| 三接收者每轮平均完成时间 | 65.68 / 67.12 ms | 33.52 / 32.10 ms |
| 打包内核平均时间 | 17.95 / 15.65 ms | 7.05 / 7.11 ms |
| 主线程重新取得运行时锁 P95 | 8.10 / 8.86 ms | 0.0008 / 0.0008 ms |
| 测试期间 Private 峰值增量 | 22.82 / 21.70 MiB | 5.18 / 4.41 MiB |

真实 TCP 对照：2 名正常玩家、1 名限速玩家和 1 名观众，固定快照 33,341 字节、运行 20 秒、实际发出 322 个快照时刻。单连接应用层已编码待写峰值由 100,882 降到 33,611 字节，下降约 67%；正常玩家各收到 322 份快照，快照年龄 P95 约 16 ms，所有玩家各 40/40 输入确认。暂停观众应用消费 5 秒后正常恢复。

限速玩家下行只有 128 KiB/s，低于产生快照的速率：新旧快照年龄 P95 分别约 4.39 / 4.73 秒，仍有明显排队。应用层待写峰值不等于全部内核、代理及网络缓冲之和；本结果不能宣称所有弱网都流畅。

真实公网私有房间：使用生产原生 RelayHostTransport/RelayClientTransport，约 5 Hz、20 秒，99/99 快照和 40/40 输入确认，首次快照通过真实原生解包并与源房间一致；快照年龄 P95 124.4 ms、输入往返 P95 138.8 ms。两端在同一台 PC，云端服务配置未改动，退出后房间归零。这不是双物理机、手机或服务器最大并发测试。
